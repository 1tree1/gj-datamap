# URBANIS Generative Urban Design — 실행 계획서 (Rhino/Grasshopper 중심)

> **버전** v1.0 · **작성일** 2026-07-16
> **범위** 지구단위계획급 대지에서 데이터·법규 기반으로 배치안을 생성하고, 일조·채광·보행·커뮤니티·쾌적성·도시열섬·바람길을 다목적으로 평가하여 강점별 최적 대안을 도출하고, 스카이라인을 고려해 건물 높이를 배분하는 워크플로우
> **툴체인** Rhino 8 + Grasshopper (생성·평가·최적화) → Rhino.Inside.Revit / IFC (BIM 상세)
> **레퍼런스 대지** 과천 지구단위계획(첨부 이미지) — 실제 제어요소를 파이프라인 입력으로 사용

---

## 0. 한눈에 보는 전체 흐름

```
[데이터·법규 입력]                [생성]                 [평가 — 다목적]              [최적화·의사결정]
KOSIS/SGIS/V-World  ┐        ┌ 규제 봉투(Envelope)   ┌ 일조·채광 (Ladybug)      ┌ Wallacei MOO
지구단위계획 지침    ┼──파싱──┼ 판상형/탑상형 매스     ┼ 바람길·열섬 (Butterfly)  ┼ Pareto Front 추출
지적·용도지역·표고   ┘        └ 층수·세대 파라미터     ┼ 보행·접근 (Space Syntax) ┼ 강점별 군집(k-means)
                                                    ┼ 커뮤니티·통경·조망       └ 대안 3~5개 라벨링
                                                    └ 용적률·수익 (제약)              │
                                                                                     ▼
                                              [스카이라인 높이 배분] → [Revit/IFC 내보내기 → 보고서]
```

핵심 사상: **"AI가 백지에서 그리는 것"이 아니라, 한국 지구단위계획의 규제 봉투를 먼저 확정한 뒤, 그 안에서 파라메트릭하게 수천 개 대안을 생성하고 환경·쾌적성 지표로 걸러내는 것.** 규제가 탐색 공간(search space)을 정의하고, 다목적 최적화가 그 안에서 파레토 최적을 찾는 구조입니다.

## 1. 대지 분석 — 지구단위계획을 데이터로 파싱

첨부한 과천 지구단위계획 도면에는 이미 도시설계가 규정한 제어요소가 담겨 있습니다. 이것을 GH의 입력 파라미터로 구조화하는 것이 1단계입니다.

### 1.1 도면에서 추출할 획지별 속성 (블록 1-1 ~ 12-2)

| 속성 | 도면 표기 예 | GH 데이터 타입 | 용도 |
|---|---|---|---|
| 용도지역 | 2종일반, 3종일반 | text/enum | 건폐율·용적률·높이 규칙 결정 |
| 건폐율(BCR) | 20, 30 (%) | number | 바닥 점유 상한 |
| 용적률(FAR) | 200(230), 160(190) | number | 연면적 상한 (기준/인센티브) |
| 최고층수 | 5층 / 15층 / 25층 | integer | 높이 상한 |
| 배치구간 | 4층이하·8층이하·10층이하·15층이하·25층허용 | polygon+cap | 부분별 높이 존 |
| 건축물 형태 | 탑상형(25층이하) / 판상형 / 직각배치존 | enum | 매스 typology 선택 |
| 벽면지정선·한계선·건축한계선 | 선형 | curve | 매스 배치 경계·정렬선 |
| 통경(축)구간 | 통경구간 | corridor polygon | 시각 축 확보(비워야 함) |
| 조망차폐율 적용구간 | 70% 이하 | number | 배경 산·랜드마크 조망 보호 |
| 공지 | 전면공지·쌓기형공지 | polygon | 건축 불가·보행 영역 |
| 보행/차량 동선 | 보행자우선도로·공공보행통로·차량출입 불허구간 | curve | 접근성·저층부 활성화 |

### 1.2 파싱 방식 (택1 또는 병행)

- **수동 리디지타이즈(권장 시작점)** — 도면을 Rhino에 언더레이로 깔고 획지 경계·배치구간·통경축을 폴리라인으로 다시 그린 뒤, 각 폴리곤에 위 속성을 `Text/Key-Value`로 태깅. `Elefront` 또는 `Human` 플러그인으로 지오메트리에 속성 부착.
- **GIS 자동 수입** — 실제 프로젝트에서는 국토정보플랫폼/V-World에서 지적·용도지역 SHP를 받아 `Heron`(GH의 GIS 플러그인)으로 좌표계(EPSG:5186) 정합하여 자동 임포트. 지구단위계획 지침은 별도 규칙 테이블(CSV)로 관리.
- **데이터 스키마** — URBANIS의 법정동/PNU 키 체계와 연결. 획지 = `parcel_id + PNU`, 규칙 = `zoning → {BCR, FAR, height_max, setback_rule}` 딕셔너리.

### 1.3 컨텍스트 입력 (환경 시뮬레이션 전제)

- **표고/지형(DEM)** — V-World DEM으로 대지 경사·주변 능선(조망차폐 판단용) 메쉬 생성.
- **주변 건물 매스** — V-World 3D 또는 건축물대장 높이로 인접 블록을 저해상 박스로 재구성(일조 그림자·바람 상호작용에 필수).
- **기상 데이터** — 가까운 기상관측소 EPW 파일(과천은 서울/수원 EPW 대체). 최다풍향·계절별 태양궤적·기온의 입력.

## 2. 한국 법·문화·풍토 제약 — "규제 봉투(Regulatory Envelope)" 생성

이 단계가 데이터·법규를 3D 제약으로 번역하는 핵심입니다. 생성 이전에 **가능 영역을 먼저 깎아내는** 방식(carving)이 한국 도시설계에 가장 적합합니다.

### 2.1 법규 → 지오메트리 변환 규칙

| 규제 | 근거 | GH 구현 |
|---|---|---|
| 건폐율 | 국토계획법 시행령·조례 | 획지면적 × BCR = 최대 바닥면적 → 매스 footprint 제약 |
| 용적률 | 지구단위계획 지정값 | Σ(각층 바닥면적) ≤ 획지면적 × FAR → 층수 상한 도출 |
| 최고 높이 | 지구단위계획 배치구간 | 배치구간별 z-cap 서피스로 매스 상단 절단(`Solid Trim`) |
| **정북 일조사선** | 건축법 제61조 (전용·일반주거) | 정북 인접대지경계선에서 높이별 후퇴(≤9m:1.5m, >9m:높이의 1/2) 사선면 생성 → 매스 클리핑 |
| 인동간격(채광) | 채광창 방향 인동거리(높이 비례) | 동간 최소거리 = f(높이) 제약을 배치 규칙에 삽입 |
| 벽면지정선/한계선 | 지구단위계획 | 매스 전면을 지정선에 정렬(강제) 또는 한계선 내 후퇴(허용) |
| 통경축 | 지구단위계획 | 통경구간 폴리곤은 건축 금지 영역(void)으로 subtract |
| 조망차폐율 70% | 지구단위계획 | 지정 조망지점(ROI)에서 배경 능선 대비 매스 실루엣 차폐율 ≤70% 검증(2단계 평가에서도 재사용) |

### 2.2 한국 문화·풍토 반영 (정성 규칙의 정량화)

- **남향 선호** — 주동 주향(main orientation)을 남–남동(진북 기준 방위각 150~200°)에 가중치. 향(orientation) 페널티 함수로 목적함수에 반영.
- **배산임수·조망** — 뒤로 산(능선)을 두고 앞을 틔우는 배치 선호를 조망축·통경축 확보로 구현. 과천처럼 관악산 자락 대지는 능선 조망 보호가 실제 지침.
- **저층부 가로 활성화** — 보행자우선도로·공공보행통로 면한 저층에 상가·부대시설·근린생활시설 배치 규칙(도면의 보행 동선과 연동).
- **위계적 오픈스페이스** — 중앙 커뮤니티 공원 + 단지별 마당의 위계. 한국 아파트 단지의 '중심 공원' 관습을 커뮤니티 지표에 반영.
- **프라이버시·시선 간섭** — 동간 정면 대향(face-to-face) 배치 회피를 세대 시선 겹침(inter-visibility) 페널티로.

> 산출물: 각 획지마다 **"이 안에서만 매스가 존재할 수 있다"는 3D Solid(Buildable Envelope)** 와, 그것을 깎는 제약 함수 세트. 이후 모든 생성은 이 봉투 내부로 한정됩니다.

## 3. 매스 생성 — 판상형/탑상형 파라메트릭 배치

과천 도면이 이미 '탑상형(25층이하) 배치구간'과 '판상형·직각배치존'을 구분하고 있으므로, typology를 파라미터로 두고 배치를 생성합니다.

### 3.1 생성 파라미터(유전자, Gene)

- **동 개수 / 배치 격자** — 그리드 간격·회전·offset.
- **Typology** — 판상형(slab, 저·중층 남향 병렬) vs 탑상형(tower, 고층 점적). 배치구간 규칙과 매칭.
- **동별 층수** — 배치구간 z-cap 내에서 정수 변수(예: 4/8/10/15/25). → 스카이라인의 주 변수.
- **주향(회전각)** — 남향 가중 범위 내.
- **동 길이·폭(판상형), 코어 위치(탑상형)**.
- **저층부 포디움/상가 유무**.

### 3.2 생성 로직

```
FOR each 획지:
    envelope   = BuildableEnvelope(획지, 법규, 지침)      # 2단계 산출
    typology   = pick(판상형|탑상형)  by 배치구간 규칙
    grid       = ParametricGrid(간격, 회전, offset)       # 유전자
    masses     = PlaceBlocks(grid, typology, 층수_i)      # 유전자
    masses     = TrimTo(masses, envelope)                # 봉투로 절단
    masses     = Enforce(벽면지정선, 인동간격, 통경void)   # 하드 제약
    FAR_used   = Σ(floor_area) / 획지면적
    IF FAR_used > FAR_max: reject/repair                 # 용적률 하드 제약
RETURN masses  # 하나의 후보 대안
```

- **하드 제약 위반은 생성 단계에서 폐기/보정**(법규는 목적함수가 아니라 제약). → 최적화가 항상 '적법한' 대안만 탐색.
- **소프트 선호(남향·프라이버시 등)는 목적함수 페널티**로.

## 4. 평가 — 다목적 성능 지표 (선택하신 6대 목표)

각 후보 매스에 대해 아래 지표를 계산합니다. 괄호는 GH 구현 도구입니다.

| # | 목표 | 정량 지표 | 계산 방법 (플러그인) | 방향 |
|---|---|---|---|---|
| 1 | **일조·채광** | 동지 기준 세대 평균 일조시간, 세대 일조 만족비율(≥연속 2h), 저층부 채광 부족 세대율 | Ladybug `Direct Sun Hours`, 인접 매스 그림자 포함 | ↑ |
| 2 | **바람길** | 보행자 높이(1.5m) 평균 풍속, 정체구역(<0.5 m/s) 면적비, 여름 통풍 확보율 | Butterfly(OpenFOAM) 또는 Eddy 간이 CFD | 정체↓·통풍↑ |
| 3 | **도시열섬 완화** | Sky View Factor, 녹지·투수면적비, 여름 평균복사온도(MRT), 표면 그늘율 | Ladybug `SVF`·`MRT`, 녹지 레이어 | 완화↑ |
| 4 | **보행·접근성** | Space Syntax 통합도(Integration)·선택도(Choice), 보행 15분 생활SOC 커버리지, 저층부 활성 길이 | DeCodingSpaces Toolkit / SpiderWeb, Turf 접근성 | ↑ |
| 5 | **커뮤니티·쾌적성** | 공용 오픈스페이스 면적·접근성, 마당 위계, 통경축 개방도, 세대간 시선간섭(프라이버시) | GH 커스텀(가시성 그래프, isovist) | 개방·프라이버시↑ |
| 6 | **조망·스카이라인** | 조망차폐율(능선 대비 ≤70%), 스카이라인 리듬 지수, 랜드마크 가시율 | isovist / 실루엣 투영 계산 | 차폐↓·리듬↑ |
| (제약) | 용적률·수익성 | 실현 FAR, 세대수, 전용면적 효율 | 바닥면적 집계 | 하한 충족 |

**정규화** — 각 지표를 0~1로 스케일(min-max)하여 목적함수 벡터 `f = [f1..f6]` 구성. 수익성(FAR)은 '최소 사업성 하한'을 만족하는 **제약**으로 두고, 나머지 6개를 **동시 최소화/최대화 목적**으로 둡니다(선택하신 우선순위 반영).

## 5. 최적화 — 다목적(MOO)로 강점별 대안 도출

### 5.1 최적화 엔진

- **Wallacei X**(권장) — NSGA-II 기반 다목적 진화 최적화. 여러 목적을 동시에 다루고 **Pareto Front**(어느 하나를 개선하려면 다른 하나를 희생해야 하는 최적 경계)를 시각화·군집화. 세대별 다이버시티 분석 내장.
- 대안: **Opossum**(모델 기반, 빠른 수렴), **Octopus**(다목적, 파레토 3D). 단일목적 스터디는 **Galapagos**.

### 5.2 "강점별 대안"을 뽑는 방법 (핵심)

다목적 최적화의 결과는 하나의 정답이 아니라 **파레토 최적해 집합**입니다. 여기서 강점별 대안을 도출합니다:

```
1) Wallacei로 N세대 진화 → 파레토 프론트의 해집합 S 획득
2) S의 목적함수 벡터에 k-means/계층군집 적용 → 3~5개 군집
3) 각 군집의 대표해에 '강점 라벨' 부여:
     · A안 "일조 우선형"   — 일조·채광 최상, 남향 병렬 판상형 경향
     · B안 "바람·열환경형"  — 바람길·SVF·MRT 최상, 동 간격 넓고 저층부 개방
     · C안 "보행·커뮤니티형" — Space Syntax 통합도·오픈스페이스 최상, 저층 활성
     · D안 "조망·스카이라인형"— 탑상형 리듬, 조망차폐 최소, 랜드마크 가시
     · E안 "균형형(니어 유토피아)" — 6개 목적의 유클리드 균형점
4) 각 대안의 레이더차트 + KPI 표 + 3D 뷰 자동 생성
```

이 방식이 사용자가 원한 "**강점에 따라 여러 개의 최적 대안**"을 정확히 구현합니다. 각 대안은 서로 다른 트레이드오프를 대표합니다.

## 6. 스카이라인·건물 높이 배분

### 6.1 높이 결정 로직 (제약 + 최적화 + 미학)

1. **하드 상한** — 배치구간 z-cap(4/8/10/15/25층)과 정북 일조사선, 조망차폐율 70%가 각 위치의 물리적 상한을 규정.
2. **최적화 변수** — 그 상한 이하에서 동별 층수는 유전자로 자유롭게 탐색되어 일조·바람·용적률에 동시 기여.
3. **스카이라인 미학 목적함수** — 단조로운 벽(wall effect) 억제와 리듬 확보:
   - *조망 그라데이션* — 도면 경향(북측/동측 고층 25층, 중심·남측 저층)을 반영해 배경 능선 방향으로 갈수록 높이 상승을 보상.
   - *리듬 지수* — 인접 동 높이차의 분산이 특정 구간일 때 가점(급락·급등·완전평탄 모두 감점).
   - *조망축 보호* — 통경축·조망지점에서의 스카이라인 실루엣이 배경 능선을 70% 이상 가리지 않도록.
4. **결과** — 각 동에 확정 층수/높이(m)가 배정된 3D 매스 + 스카이라인 입면 프로파일 자동 생성.

> 과천 사례처럼 "탑상형 25층은 특정 배치구간에만, 남측 저층 존은 8층 이하, 능선 조망은 보호" 같은 실제 지침이 그대로 상한 서피스로 들어가므로, 생성된 스카이라인이 지구단위계획과 정합합니다.

## 7. BIM 연동 — Rhino/GH → Revit / IFC

1. **선정 대안 확정** → GH 매스에 층·세대·용도 메타데이터 부착.
2. **Rhino.Inside.Revit** — GH 컴포넌트로 Revit에 Mass/Generic Model 또는 층별 Floor·Wall로 직접 생성. 향후 Revit에서 실시 설계 전개.
3. **IFC 내보내기** — 실무 교환·URBANIS 웹 재업로드용으로 `IFC4` export(Rhino 8 내보내기 또는 IfcOpenShell 후처리). 대안 KPI를 IFC PropertySet에 기록.
4. **대안 (오픈소스 경로)** — Revit 미보유 시 Blender + BlenderBIM(IfcOpenShell)으로 동일 IFC 파이프라인 구성 가능(향후 옵션).
5. **보고서** — 대안별 KPI 표·레이더차트·3D 뷰·스카이라인 입면을 DOCX/PDF로 자동 출력(URBANIS Module 5 연동).

## 10. 즉시 시작(Quick Start) — 1주 미니 실험

전체를 짓기 전에, 파이프라인 개념을 가장 빠르게 검증하는 최소 실험:

1. 과천 도면에서 **획지 하나(예: 블록 5, 직각배치존·15층이하)**만 리디지타이즈.
2. 건폐율·용적률·15층 z-cap·정북 일조사선으로 **Buildable Envelope** 생성.
3. 판상형 3~4동을 격자·회전·층수 3개 유전자로 파라메트릭 배치.
4. Ladybug **동지 일조시간** 하나만 목적함수로 **Galapagos** 단일목적 최적화.
5. 최적·차선·저성능 3개 매스를 나란히 렌더 → 파이프라인 감각 확보.

이 미니 실험이 돌아가면, 목적함수를 6개로 확장하고 Galapagos → Wallacei로 바꾸는 것이 다음 스텝입니다.

## 11. 리스크·주의점

- **일조사선·인동간격은 조례별로 상이** — 과천시(경기도) 건축조례 실제 수치를 P1에서 반영. 규칙 테이블을 조례 파라미터로 외부화해 도시 이전(transfer) 가능하게.
- **CFD(바람) 비용** — Butterfly 정밀 CFD는 대안당 수 분~수십 분. 최적화 루프에서는 간이 대체지표(SVF·개구율) 또는 대리모델(surrogate)로 근사하고, 최종 후보만 정밀 CFD.
- **평가–최적화 속도** — Ladybug 전체를 매 세대 돌리면 느림. 저해상 프록시로 탐색 후 상위 대안만 고해상 재평가(2-tier).
- **문화 규칙의 주관성** — 남향·프라이버시 가중치는 사업 성격에 따라 조정 가능한 슬라이더로 노출.
