---
description: 수집한 자료를 index.csv 형식으로 편입
---

편입할 자료: $ARGUMENTS

1. `archive/00_meta/index.csv`를 읽어 기존 id 체계를 확인한다.
2. 파일명을 규약대로 바꾼다: `{코퍼스}-{스케일}-{YYYYMMDD}-{발행주체}-{슬러그}-v{n}.{ext}`
   - 코퍼스: A(계획·제도) B(사업·행정기록) C(공간·통계) D(선행연구) E(사례·공모전)
   - 스케일: S1(부지 79,438㎡) S2(원도심 1km) S3(경주시+폐선축 80.3km)
3. `index.csv`에 한 행을 추가한다. 필드:

```
id, corpus, scale, title, issuer, issuer_type, doc_type,
date_issued, date_acquired, url_source, access, tier, uses,
spatial_key, crs, temporal, license, citation_key, claims,
supersedes, status, axis, proxy_for
```

- `tier`: T1–T4 (수집 시점에 반드시 부여)
- `uses`: URB(지구단위계획) / COMP(혁신지구 공모) / RES(연구·논문) / DUP(URBANIS 데이터 인프라) — 복수 가능
- `axis`: 시간 / 인구·쇠퇴 / 경제 / 이동 / 환경·재해 / 물리인프라 / 유산·경관 / 방법론
- `proxy_for`: **이 자료가 직접 측정하지 못하는 무엇의 대리 지표인가.** 기록하지 않으면 반년 뒤 자기 분석의 논리를 재구성할 수 없다

4. 문서라면 `D_literature/notes/`에 YAML front-matter 노트를 만든다:

```yaml
id:
tier:
scale:
uses:
claims:      # 이 자료가 주장하는 것
page_refs:   # 페이지 단위
contradicts: # 어느 자료와 충돌하는가 ← 가장 중요
```

`contradicts` 관계를 전수 추출한 "모순 지도"가 곧 지구단위계획 과제목록이자 논문 문제제기가 된다.

5. 처리본은 EPSG:5187로 변환했는지 확인. 원본은 변환하지 않는다.
