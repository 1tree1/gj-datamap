## 2. 이 프로젝트의 논증 구조 — 코드보다 먼저 이해할 것

이 작업은 "AI가 더 나은 계획안을 그렸다"가 아니라 **"기존 제안들이 어느 축을 희생했는지 측정했고, 그 축을 회복하는 해가 존재함을 보였다"**를 목표로 한다.

- 고정 입력은 **구역 경계선 하나**뿐. 2026.1 공고 결정도의 가구·획지·용도는 참고이며 100% 변경 가능.
- 417쪽 경주시 발주 연구의 (옛)경주역 부지 제안 15건 + 공고안 + 참조사례 2건 = **비교 대상 18개**를 동일한 5개 목적함수로 평가해 목적공간에 찍는다.
- 목적함수 5개는 그 417쪽 연구의 도시설계 5개 방향과 거의 일대일 대응시킨다 → "제가 골랐습니다"가 아니라 "발주 연구의 방향을 측정 가능한 형태로 옮겼습니다".

세부는 `docs/40_engine/구경주역_최적화엔진_Part5.md` 참조.

## 3. 작업 규칙 (이 저장소에서 지켜야 할 것)

### 3.1 출처 등급 — 모든 주장에 붙인다

- **T1** 법정문서 (법령·조례·고시·승인계획·협약)
- **T2** 공공발간 (용역보고서·과업지시서·국책연구·통계 원자료)
- **T3** 학술
- **T4** 언론·2차자료

**공모 대응과 지구단위계획 문서에는 T1–T2만 쓴다. 논문에는 T4를 배제한다.**
현재 현황 앵커(사업비·면적·MOU 등)는 대부분 언론 경유 T4다 → 원문 치환이 미완료라는 사실을 답변에 명시할 것.

### 3.2 숫자는 출처 없이 쓰지 않는다

`docs/` 안의 수치도 상당수가 "인용 전 원문 확인 필요" 상태다. 예: 상업지역 0.22%, 주차난 불만 38.8%, 경의선숲길 102,008㎡ 등. 인용할 때는 `[T4, 원문 미확인]` 같은 꼬리표를 붙인다.

### 3.3 스케일을 섞지 않는다

- **S1 SITE** 79,438㎡ 성동동 일원 — 키: PNU 19자리
- **S2 DISTRICT** 원도심 보행권 반경 1km (황오·성동·노서·노동동) — 키: 집계구코드, H3 r8
- **S3 CITY/CORRIDOR** 경주시 전역 + 폐선축 80.3km — 키: 법정동코드 10자리, H3 r7

S3 통계로 S1 프로그램을 정당화하지 않는다.

### 3.4 제약은 페널티가 아니라 불가능이다

규제 위반은 목적함수 페널티로 넣지 않는다. 페널티로 두면 "조금만 위반하고 점수 많이 따는" 해가 나온다. `constraints/compile.py`에서 `buildable` 마스크로 잘라낸다.

### 3.5 생성 결과를 그대로 제출하지 않는다

최종안은 파레토 해 하나를 사람이 손으로 다듬은 것이어야 하고, **조정 내역도 추적표에 남긴다**.

### 3.6 언어

- 사용자와의 대화, 계획 문서, 코드 주석: **한국어**
- 코드 식별자·파일명(신규): 영문 소문자 스네이크

## 4. 이미 내려진 판단 (다시 논쟁하지 말 것)

| 판단 | 이유 |
|---|---|
| 지구단위계획 도면 확산모델 학습 **기각** | 추적표에 "생성모델이 그렸다"를 쓸 수 없음 / 개발 전후 정렬 데이터셋 부재 / 8GB VRAM 한계 |
| 도시 이미지 학습 → 배치 생성 **기각** | 래스터 출력은 필지 경계·면적표를 만들지 못함. 산출물은 그림이 아니라 폴리곤과 숫자 |
| **규칙기반 생성 + 다목적 최적화(NSGA-III) 채택** | 모든 결정이 파라미터로 추적됨, 출력이 처음부터 벡터·수치, CPU로 구동 |
| 학습 요소는 3곳만 | SAM(과거 항공사진 건물 추출) / 대리모델(LightGBM) / 선택적 RL |
| RL은 지금 불필요 | Tsinghua 모델은 수백 셀 규모용, 우리 획지는 20–40개 → NSGA-III 정수 유전자로 충분. RL은 방법론 비교용으로만 |
| 단계별 개발순서는 MILP | 가구 8–20개 × 4단계 = 결정변수 80개 → OR-Tools CP-SAT / PuLP+CBC로 초 단위 정확해 |
| 목적함수에 가중치를 넣지 않음 | "왜 이 가중치인가"에 답할 수 없음. 파레토 전선을 통째로 내고 대안 A–E로 제시 |
| SKT/KT 상용 유동인구 구매 안 함 | 관광 데이터랩·SGIS로 대체 |
| 아카이브는 로컬 폴더 + 메타데이터 CSV/YAML | Notion DB나 PostGIS 하이브리드가 아님 |

## 5. 사례에서 이미 확정된 교훈 (계획 판단에 그대로 쓸 것)

1. **국내 폐선부지 21개 중 면적(面的) 개발은 안동·진영·진주뿐.** 8ha에 가구·획지를 그리는 문제의 국내 선례는 사실상 **구 안동역 하나**. 해외 비중이 커질 수밖에 없다.
2. **1단계는 연결·기반·보행.** 구 안동역 1단계 = 연결도로 220m + 지하주차 257면 + 산책로 790m. 셋 다 어떤 미래 프로그램에도 필요하고 되돌릴 필요가 없고 즉시 체감된다. 단, 경주는 매장문화재 때문에 지하주차를 1단계에 넣을 수 없다.
3. **비가역 투자는 뒤로.** 교토 우메코지 29년: 공원(1995) → 수족관 민간제안(2012) → 철도박물관(2016) → 전용역(2019). 민간자본은 공원 개원 **13년 후**에 들어왔다. 빌릴 것은 기간이 아니라 **순서**.
4. **단일 대형은 울산형.** 79,438㎡ 한 곳에 3,822억을 몰아넣으면 "도심 속 외딴 섬"이 된다. 부산 혁신도시는 93.5만㎡를 4개로 쪼개 기존 도심에 끼워 넣어 정주만족 1위(61.6%). → **분산 삽입형 대안 시나리오를 반드시 함께 낼 것.**
5. **주거 부재가 결정도의 최대 공백.** 부산 대연지구 2,300가구 → 1,300명 정착. 경주 결정도에는 주거가 없다 → 저녁 6시 이후 죽는 구역.
6. **방문객 수를 성공 지표로 삼으면 전주의 10년 뒤.** 성과지표는 **(방문객·체류시간) / (거주인구·생활업종 비율·야간활동)** 두 축으로 항상 나란히 보고한다. 관광 업종이 늘고 생활 업종이 주는 것은 회복이 아니라 **치환**.
7. **성공 지표는 "건물이 방향을 바꾸는가".** 광주 푸른길에서 레일을 등지던 건물들이 푸른길 쪽으로 출입문을 냈다. 부지 경계 인접 필지의 **주 출입구 방향**을 항공사진·로드뷰로 시계열 추적 — 설문이 아니라 물리적 사실.
8. **선형 축은 한 점만 끊겨도 전부 무력화된다.** 접근성 f₁은 '횡단축 개소 수'가 아니라 **연속성 + 가장 약한 지점의 통과 폭**(최소값 지배)으로 측정한다.
9. **조성 조직이 아니라 운영 조직을 설계한다.** (사)푸른길이 광주 사례를 특별하게 만들었다. 계획 설명서에 준공 후 **운영 주체와 재원**을 명시.
10. **실패 사례는 성공 사례보다 심의에서 강하다** — 검토했음을 증명하기 때문. 울산 우정혁신도시, 트렌토 Le Albere, 발렌시아 예술과학도시를 `alternatives` 열에 명시.

## 7. 자주 쓰는 명령

```bash
# 제약 컴파일 (경계 면적을 즉시 출력해 좌표계 오류를 눈으로 잡는다)
gjplan compile   --boundary archive/C_data/processed/site.shp --layer BOUNDARY

# 대리모델 학습 (정직평가 300~1000개를 하룻밤 돌린 뒤)
gjplan surrogate --samples 500

# 다목적 최적화
gjplan optimize  --pop 200 --gen 300

# 단계별 개발순서 MILP
gjplan phase     --option E

# 내보내기 (면적표 합계 = 구역 총면적 검증 필수)
gjplan export    --option E --formats dxf,xlsx,3dm
```

**DWG는 직접 읽지 않는다.** ezdxf는 DXF만 읽는다 → Rhino/QGIS로 변환하거나 국토정보플랫폼에서 SHP로 받는다.
**레이어 규약**: `BOUNDARY`(닫힌 폴리라인 1개), `FIXED_*`, `ANCHOR_*`(선택).
**Rhino는 최적화 루프 밖**에 둔다. 대안 5개를 3dm으로 내보내 검토·수정하고, 수정 파라미터를 `config.yaml`에 반영해 재실행.

## 8. 하드웨어·예산 제약

- RTX 3070 / RTX 4060 (각 8GB VRAM), i9
- 추가 지출 목표 **0~30 USD**. 유일한 지출 후보는 RL 학습이 느릴 때 RunPod/Vast RTX4090 스팟
- SAM은 ViT-**L** (ViT-H는 8GB에서 빠듯)
- SD1.5+ControlNet / SDXL-Turbo는 **발표용 렌더만**. 계획 도면에는 절대 사용 안 함
- 병목은 GPU가 아니라 **평가 횟수**다. 개체 200 × 세대 300 = 6만 회. 대리모델 없이 정직 평가로 루프를 돌면 첫 실행에서 몇 주가 사라진다

## 10. 함정 목록 (반복해서 발생함)

- 보도자료를 데이터로 착각
- 규제를 한 겹만 보기 (4겹 중첩 필수)
- 스케일 혼용 (S3 통계로 S1 정당화)
- 좌표계 후처리 (EPSG:5187 변환은 읽자마자)
- `gaps.md` 미기록 — 못 구한 자료를 기록하지 않으면 반년 뒤 자기 분석의 논리를 재구성할 수 없다
- 부지를 폐선축 80.3km와 분리해서 보기
- 차원을 키우는 것 — "도로를 자유롭게 그리게 하자". 50차원을 넘으면 NSGA-III가 수렴하지 않는다. 선형 부지 구조를 이용해 차원을 낮게 유지하는 것이 설계의 핵심
- `proxy_for` 미기록 — 건물 에너지 사용량은 '에너지' 데이터가 아니라 **공실의 프록시**다
