🏗️ Dual-Scale BIM Platform

도시 스케일 + 건축물 스케일 · IFC 기반 · 시뮬레이션 통합 · 실현가능성 분석

결론: 기술적으로 가능합니다

필요한 오픈소스 도구가 모두 존재합니다. IFC 읽기/쓰기는 IfcOpenShell, 환경 시뮬레이션은 EnergyPlus/Radiance/OpenFOAM, 행태 시뮬레이션은 MATSim/SUMO, 웹 3D 뷰어는 web-ifc + Three.js, 도시 스케일 시각화는 deck.gl/CesiumJS로 구현 가능합니다.

단, "하나의 통합 프로그램"으로 만들면 Revit + ArcGIS + EnergyPlus를 혼자 만드는 것과 같습니다. 현실적 전략은 "공유 데이터 허브 + 2개의 특화 뷰어" 구조로, 각 스케일에 맞는 기능을 점진 구축하는 것입니다.

⚠ 솔직한 경고

Revit은 30년간 500+명의 엔지니어가 만든 프로그램입니다. Rhino는 25년간 전업 팀이 개발했습니다. "BIM 프로그램을 만들겠다"는 것은 이들과 경쟁하겠다는 의미가 아니라, 특정 분석 워크플로우에 특화된 도구를 만들겠다는 의미여야 합니다. 즉, 모델링 도구가 아닌, 분석·시각화·의사결정 지원 도구가 현실적 목표입니다.

IFC 기반 워크플로우: 구체적으로 어떻게?

IFC 데이터 흐름
[ Revit / ArchiCAD / Bonsai(Blender) ]
              │ .ifc 파일 내보내기
              ▼
┌─── IfcOpenShell (Python 백엔드) ───┐
│                                    │
│  1. 파싱: model = ifcopenshell.open("building.ifc")
│  2. 추출: walls = model.by_type("IfcWall")
│  3. 속성: psets = ifcopenshell.util.element.get_psets(wall)
│  4. 면적: area = ifcopenshell.util.element.get_container(space)
│  5. 좌표: site_coords = get_site_address(model)
│                                    │
│  ┌───────────┐  ┌───────────────┐  │
│  │ geometry → │  │ properties →  │  │
│  │ glTF/OBJ   │  │ JSON/DB 저장  │  │
│  └─────┬─────┘  └───────┬───────┘  │
└────────┼────────────────┼──────────┘
         │                │
         ▼                ▼
┌── web-ifc ──┐   ┌── 시뮬레이션 변환 ──┐
│ 브라우저 3D  │   │ IFC → EnergyPlus  │

│ 요소 선택   │   │ IFC → JuPedSim    │

└─────────────┘   └──────────────────┘
IFC → 시뮬레이션 변환의 현실적 난이도

IFC → EnergyPlus: 가장 성숙한 경로. Space Boundary(IfcRelSpaceBoundary)를 이용하여 열구역을 자동 추출하는 연구가 많음. 단, 실무 IFC에서 Space Boundary가 누락되는 경우가 빈번하여 geometry 기반 자동 생성이 추가로 필요합니다.

IFC → OpenFOAM: IFC geometry를 STL로 변환 (IfcConvert)한 후 snappyHexMesh로 메시 생성. 이 경로는 비교적 직선적이지만, CFD 메시 품질 보장이 어려워 수동 조정이 자주 필요합니다.

IFC → 보행 시뮬레이션: IfcSpace에서 보행 가능 영역을 추출해야 하는데, IFC 모델의 IfcSpace 정의 품질에 크게 의존합니다. 잘 만들어진 모델에서만 자동화 가능.

05

현실적 개발 로드맵 (1인 개발자 기준)

PHASE 1 — MVP
도시 데이터 뷰어 + IFC 뷰어 (분리)
Program A: 지도 + 데이터 레이어 + 대시보드. Program B: IFC 로드 + 3D 탐색 + 속성 조회. 시뮬레이션은 아직 없음. 데이터 파이프라인 확립.
⏱ 2~3개월
PHASE 2 — 접근성 + 일조
15분도시 등시선 + Three.js 일조 시뮬레이션
Program A에 Valhalla 등시선 추가. Program B에 실시간 일조 시뮬레이션(SunCalc + Shadow). 두 프로그램 간 좌표 연동 (IFC 건물을 도시 맵 위에 표시).
⏱ 2~3개월
PHASE 3 — 에너지 + 교통
EnergyPlus 연동 + SUMO 교통 시뮬레이션
IFC → EnergyPlus 자동 변환 파이프라인. SUMO 교통 시뮬레이션 결과를 deck.gl TripsLayer로 표현. 법규 자동 검토 (건폐율/용적률).
⏱ 3~4개월
PHASE 4 — 고급 시뮬레이션
CFD 풍환경 + 보행 시뮬레이션 + 지식그래프
OpenFOAM CFD 풍환경 (가장 어려움). JuPedSim 보행. OWL 온톨로지 기반 법규 추론. 위성 변화감지. GNN 예측 모델.
⏱ 4~6개월
PHASE 5 — 통합 + XR
Grasshopper/Unity/Dynamo 연계
분석 결과 → Grasshopper 파라메트릭 설계. Unity XR 몰입형 체험. IFC roundtrip (결과를 IFC Pset으로 재기록).
⏱ 3~4개월
총 예상: 14~20개월 (1인 기준, 풀타임)

하지만 Phase 1만 완성해도 이미 한국에 없는 도구입니다. "도시 데이터를 인터랙티브 맵으로 보면서 IFC 건물 모델을 동시에 탐색"하는 플랫폼은 현재 존재하지 않기 때문입니다. MVP부터 빠르게 만들고, 실제 프로젝트에 써보면서 확장하는 것이 핵심 전략입니다.

한 줄 요약

가능합니다. 단, "BIM 프로그램"이 아닌 "IFC 기반 도시-건축 통합 분석 플랫폼"으로 정의하세요. 모델링은 Revit/Rhino/Bonsai에 맡기고, 알렉산더의 플랫폼은 "데이터 → 분석 → 시뮬레이션 → 시각화 → 의사결정" 파이프라인에 집중하세요. 이것이 시장에 없는 것이고, 알렉산더의 기술 스택(Rhino/GH + Revit/Dynamo + Unity + Python/ML)에 완벽히 부합하는 영역입니다.
