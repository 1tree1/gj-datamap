## 요약

1. **Forma 단독으로 요구 수준을 채우는 단계는 없습니다.** ⓪ 반입·④ 환경 평가는 조건부·부분, ⑦ 반출은 형상만 단독 가능하고 분석 수치는 SDK로만 되며, ①②③과 ⑥의 대안 비교는 SDK로 구현할 수 있으나 채택하지 않고(Python 패키지·병렬·추적·면적표 정본), ⑤ 밀도 도출과 ⑥ 다목적 최적화는 기능이 없습니다 [판단, A §3, §1.2]. 문헌 판정이므로 첫날 X0(Forma 단독 시도, 반나절)으로 실측하고, Forma의 역할은 X0 뒤 U-0으로 정합니다.
2. **파이프라인은 모듈 13개입니다**(M0 입력 정합 ~ M11 사람 조정 + M12 Rhino 실행기). M2~M7은 유전자 한 벌 → 대안 하나의 결정론적 함수이고 M8(pymoo NSGA-III)이 반복 호출합니다. 엔진은 시스템 Python 3.12에서 돌고, Rhino는 M12(엔진 실행·결과 불러오기)·검토·손 조정을 맡으며 루프 밖에 있습니다.
3. **사용자 축은 Rhino 작업 사본의 `FIXED_AXIS_*` 중심선과 폭·등급 속성으로 읽습니다.** 주 가로망은 사용자 축 그대로이고, 엔진은 보조 골목·획지 분할선만 인접 사용자 축에 평행·수직으로 만듭니다. 결정변수는 R24(프로그램 템플릿 포함), 형태 τ를 더한 R26은 W5 첫 실행입니다. 「고정 입력은 경계선 하나」의 예외라 U-1이 필요합니다.
4. **시간 예산.** 생성 1회 62 ms는 단순 벤치의 하한이며 11-06 관문에서 실측으로 바꿉니다. 실측 전 병렬 배수는 8배로 보수 계산해 3목적 R24(9,200회)는 약 5–20분 + 전선 해 수 × 1.27 s ÷ 8(K9′)입니다 [산정·가정, §6.5].
5. **획지 GSI·L 등급은 데이터 범위에서 산식으로 만든 입력 [가정]이고, 대안·전체 GSI·FSI·L은 결과입니다.** 상한은 마스크, S2 조직 분위는 등급표 근거와 f₄(island 분모·물리 FSI·정본 (a)), 하한과 평균 L ≥ 2.0은 전역 제약, 사례 밴드와 띠 (c) 1.12는 사후 점검 열입니다. 결과는 네 분모 × (GSI·물리 FSI·법정 FSI)로 보고합니다.
6. **환경은 루프 안 제약(높이 h_min~h_max·인동 0.5H·축 연속 C-8)과 최종 3–5안 검증으로 나눕니다.** 무작위 100안에서 K9′(동지 2.5D 그림자) 분산이 크면 일조를 네 번째 목적으로 올릴지 U-22로 묻습니다. 판례 일조·SVF·바람·UTCI는 루프 밖이고, Eddy3D는 1안 × 8풍향, EPW는 포항 TMYx 대체입니다.
7. **일정.** 2주(11-08)는 화면 1(Rhino 명령 한 번으로 무작위 대안 20개)까지, 화면 2(파레토·M1~M4·V0)는 W4 말(11-22)입니다. 작업일 합 22.0–22.5일에 버퍼 4.5–5.0일(20–23%)을 둔 한 표로 맞췄습니다 [가정, §7.2].
8. **엔진을 막는 결정은 셋입니다.** U-1 축 고정, U-2 처리본 프레임(기본 EPSG:5187 228,074.03㎡), U-7 용도지역 변경 범위(자연녹지를 유지하면 GSI 0.20·FSI 1.0 상한 [T1, 경주시 도시계획 조례 제81·86조, 조문 재확인 대기]이라 등급표 전체가 불가능). 첫날 할 일은 바로 아래 상자에 있습니다.

### 0.4 결과 문장

- **MVP(학부 최종)**: 「사용자 골격 위에서, 같은 골격의 V0(채택 매스 v1)와 최종 도면(41동)이 어느 축을 희생했는지 측정했고, 그 축을 회복하는 해가 있음을 보였다」 [D §2.6]. V0는 축 ① B1 구간 단절(C-8)로, 최종 도면은 고도지구 20 m 초과로 둘 다 「제약 밖」 비교점입니다(§6.8).
- **확장판(공모·논문)**: CLAUDE.md §2의 문장 — 비교 대상 18개(연구 15건 + 공고안 + 참조사례 2건)를 같은 목적공간에 찍고, 사용자 골격 자체가 지배당하는지를 축 해제판(F47)으로 검사합니다. 골격을 고정한 MVP로는 「골격까지 포함한 비교」가 성립하지 않습니다.
- 쓰지 말 문장은 §4.6에 있습니다.

### 1.3 Forma의 역할 — X0 전 기본값과 U-0

X0 전 기본값은 **최적화 루프 밖의 「검증 계측기 + 컨텍스트·발표 무대」**입니다 [판단, A §9.1]. 다만 이 기본값은 문헌 판정만으로 정한 것이고, 2026-10-24 사용자 방향은 「도출한 값으로 Forma에서 매스·계획」이었습니다. 그래서 첫날 X0(§1.4)으로 Forma 단독 작업을 실측하고, 결과를 보고 **사용자 결정 U-0**(Forma = 주 작업·비교 무대 / 검증 계측기)으로 역할을 정합니다.

- X0 결과와 무관하게 엔진(M2~M8)은 만듭니다. 최적화 루프 안의 생성은 Forma 밖이어야 하기 때문입니다(⑥ 다목적 최적화 기능 없음, ④ 루프 안 기능 없음).
- X0에서 통과한 단계는 사용자가 Forma에서 손으로 대안을 만들고 비교하는 무대로 쓰고(U-0 「주 무대」), 엔진 결과를 같은 지표로 그 옆에 올립니다. 실패한 단계는 Forma에서 하지 않고 엔진·Rhino 결과만 씁니다.
- ⑤ 밀도 범위 도출, ⑥ 다목적 최적화, 면적표 정본은 U-0와 상관없이 Python에 남습니다(기능 없음).

|---|---|---|

### 2.3 데이터 흐름과 파일 규약

- **프레임**: 처리본은 EPSG:5187입니다(CLAUDE.md §1·§10 「읽자마자 변환」). M0가 R(대지 3dm, = EPSG:5179 격자 + 이동 `X5179 = R − (11,616.38, −796.58)`)과 L(`R = L + (1,166,600, 1,761,100)`)을 읽자마자 정점마다 5179 → 5187(pyproj, always_xy)로 바꿉니다 [산정, B §6.1]. 3dm으로 내보낼 때만 5187 → R로 되돌립니다(국소 축척 1.000108·회전 −0.8785°이므로 이동만으로는 안 됨). 변환식·소스별 원 좌표계·정확도는 `frames.json`에 적습니다. U-2에서 사용자가 R을 정본으로 고르면 「CLAUDE.md §1 예외」로 추적표에 남깁니다.
- **Forma 반출**: 요소 좌표는 프로젝트 SRID + refPoint 상대값이고 `geoReference`의 SRID는 프로젝트와 같아야 합니다 [T4·SDK, `project.d.ts`·`integrate.d.ts`]. `to_forma.py`와 OBJ 지형 반출은 모두 정점마다 엔진 좌표(5187) 또는 R → EPSG:5179 → `Forma.project.get().srid`로 바꾼 뒤 `refPoint`를 뺍니다. EPSG:4326 GeoJSON을 바로 올리는 경로는 쓰지 않습니다.
- **ID**: 가구 `B1`–`B9`(북→남, 서→동, D의 번호), 획지 `B{b}-L{k}`(가구 북서 모서리에서 접도 변을 따라 시계 방향), 동 `B{b}-L{k}-M{m}`. 같은 유전자 + 같은 시드면 같은 ID가 나와야 손 조정 차이를 획지 단위로 계산할 수 있습니다(Vanegas 외 2012의 지속성 [T3, C §3.1]).
- **내부 형식**: shapely 객체 + WKB 피클. MVP는 geopandas 없이 돕니다(f₅①은 networkx만). cityseer 5.8.0은 geopandas·rasterio·pyogrio·osmnx·statsmodels를 요구하므로 [T4·PyPI] f₁을 편입할 때(W5 이후) 설치합니다. 교환 형식은 GeoJSON(EPSG:5187, `crs` 명기)과 3dm입니다.
- **3dm 단위**: 원본·사용자 마스터 3dm은 단위 표기가 mm(1단위 = 1 m)이고 엔진 출력은 Meters입니다. 사용자가 대안을 기존 mm 파일에 Import·붙여넣기·Worksession으로 합치면 Rhino가 단위 차이를 축척으로 바꿀 수 있습니다 [판단, 확인 대기: Rhino 8 Import 동작 시험 필요]. 그래서 ① 대안 수정은 `alt_*.3dm` 사본에서만 하고 다른 파일로 Import하지 않습니다(§3.12). ② 3dm을 읽는 모든 코드(M0·M9 재읽기·`diff_3dm.py`·`verify_import.py`)는 첫 줄에서 `ModelUnitSystem`을 읽고 경계 bbox **311.07 × 947.93 m ± 0.1 m**(R 프레임) [산정, B §1]를 assert합니다. 어긋나면 축척(예: 1,000배)을 추정해 보고하고 멈춥니다. ③ Ladybug·Eddy3D·Forma 플러그인용 작업 사본도 같은 assert로 확인합니다. Meters가 아닌 3dm은 Ladybug 기본 오프셋이 100 m가 되는 문제도 있습니다 [산정, C §1.3].
- **레이어 규약(작업 사본·출력)**: `BOUNDARY`, `FIXED_AXIS_NS`·`FIXED_AXIS_EW`·`FIXED_AXIS_HIST`·`FIXED_PATH_VIEW8`·`FIXED_HWARANG20`(중심선, 사용자 문자열 `width`·`class` = 보행/차도/공원), `FIXED_ROAD_N`·`FIXED_RING`(외곽도로·보도)·`FIXED_STATION`·`FIXED_HERITAGE`, `ANCHOR_ENTRY` [판단, C §2.1·§9.4-2]. 원본 레이어명(`대지경계선`·`지형_*`)은 `config.yaml` 별칭 표로 읽습니다. `FIXED_AXIS_*`가 아직 없으면 M12가 `site_inputs.geojson` 중심선으로 레이어를 처음 만들고, 그 뒤 축 수정은 작업 사본에서 합니다.

### 3.1 M0 입력 정합

- **목적**: 흩어진 프레임(R·L·road_sel·콘타 O·P·5179·5187)을 정본 프레임 하나(EPSG:5187)로 모으고, 엔진이 읽을 고정 입력을 한 파일로 만듭니다.
- **알고리즘**
  1. 3dm을 열자마자 `ModelUnitSystem`과 경계 bbox를 읽어 C-1 단위 assert를 합니다. 원본 대지 3dm은 표기가 Millimeters이고 bbox 311.07 × 947.93이면 「1단위 = 1 m」로 읽습니다 [산정, B §1]. 다른 축척이면 추정 배율을 보고하고 멈춥니다.
  2. 작업 사본(`rhino/site_work_m.3dm`)의 `BOUNDARY`와 `FIXED_AXIS_*` 중심선·`width`·`class`를 읽습니다. 작업 사본에 축 레이어가 아직 없으면 `site_inputs.geojson`의 `boundary`·`axis_band`·`road_polygon`·`axis_centerline_in_site`·`vehicle_entry`·`station`·`heritage`를 첫 입력값으로 씁니다(R 프레임, 좌표 mm 반올림).
  3. `model.pkl`(V0 획지·지정 비움·외곽 보도), `ctx_fixed.pkl`(주변 22,621동), `district.pkl`(문화재·관광지)을 L → R → 5187로 옮깁니다. pkl은 전역 참조가 `shapely.io.from_wkb`·numpy뿐임을 먼저 확인하고 엽니다(B가 쓴 방식) [산정, B §3].
  4. `frames.json`에 변환식 전부(B §6.1 표)와 소스별 원 좌표계·변환 경로·pyproj 정확도를 적습니다.
  5. 1 m 미만 변 16개는 엔진 안에서는 그대로 둡니다. Forma 반출용 사본에서만 `simplify(0.05)`를 쓰고 전후 면적 차를 기록합니다 [판단, B §1.2].
  6. 같은 날 `requirements_mvp.txt`(pymoo 0.6.2·networkx·scipy·openpyxl·pyyaml)를 설치하고 `pip check`를 통과시킵니다. 확장용 `requirements_ext.txt`(cityseer·geopandas·lightgbm·ortools·momepy·ladybug-geometry-polyskel·pandas)는 따로 둡니다.
- **파라미터**: 없음(전부 고정). `hwarang_mode`(A / vehicle) 스위치 1개 — 기본 A(U-3).
- **검사**: C-1. GeoJSON 경계와 3dm 경계의 Hausdorff ≤ 0.001 m(mm 반올림) [판단], V0 경계(118점)와 Hausdorff ≤ 0.05 m [판단](현재 0.042 m [산정, B §0-1]). EPSG:5187 228,074.03㎡와 R 228,024.83㎡를 함께 출력합니다.

**f₅① 정의** — ① 기존 성분 P_ex = Σ(구역 밖 동의 바닥면적 × h ÷ 3.5 m) × ρ. 자료는 `ctx_fixed.pkl` 22,621동이고(구역 안 385동 `inside` 제외), 이 파일에는 용도 속성이 없어(속성은 `g`·`h`·`z0`·`inside`·`id` [산정, 로컬 확인 2026-10-26]) 주거·비주거를 가리지 못합니다 → 「용도 미구분」 꼬리표. ρ(인/연면적㎡)는 [가정]이며 값은 `config.yaml`(미정). `proxy_for` = SGIS 집계구 인구(D11, 키 미발급), 등급 [가정]. 키가 발급되면 집계구 인구를 건물 연면적 비례로 배분한 값으로 바꿉니다. ② 계획 성분 = 계획 세대 × 가구원 수 [가정, `work/20261008_youth_housing`]. ③ 「공원·광장」 집합에는 고정 보행녹지 31,778㎡ [산정, D §7.2]를 넣습니다 [판단]. 이 경우 p_os·t_os′가 f₅①을 거의 움직이지 못할 수 있어 변별력 검사 항목에 넣습니다. ρ가 두 성분의 상대 크기를 정하므로 두 성분을 따로 보고하고 ρ 밴드에서 순위가 바뀌는지 봅니다 [판단].

- **변별력 검사(무작위 100안, 11-16)**: f₁ 분산, f₄ 최댓값이 특정 가구(예: B2 공공청사)에 묶이는지(묶이면 p90, D-08 [실행모델 §3.2]), f₅①의 분산(고정 녹지 포함), K9′ 분산(U-22 판단 근거), θ_lot·τ의 기여. 축을 고정하면 f₁을 움직이는 유전자는 s_lane·w_lane·획지 출입뿐이라 분산이 작을 수 있고, 그러면 f₁은 보고 KPI로 내리고 MVP는 3목적(f₃·f₄·f₅①)입니다 [D §2.5].

## 4. 용적률·건폐율 도출 절차

### 4.1 「데이터에 근거한」의 뜻

「구경주역 최적 용적률은 ○○%」라는 한 값은 만들지 않습니다. 획지 GSI·L 등급표는 데이터 범위에서 산식으로 만든 **입력 [가정]**이고(§4.3 단계 4), 대안·전체의 GSI·FSI·L은 **결과**입니다. 데이터에 근거한다는 말은 다음 세 묶음을 모두 보인다는 뜻입니다 [D §3.2].

1. **데이터에서 온 범위와 그 범위가 유전자 정의역에 들어간 방식** — 상한(법정 [T1]), 조직 정합 범위(S2 실측 분포 [산정]), 하한(프로그램 수요 [산정·가정]), 사례 밴드(밴드 B [가정]). 범위마다 출처 등급이 붙고, 최적화 전에 「도출 밴드 표」(`density_band.xlsx`, W1)로 먼저 냅니다.
2. **파레토 전선 위 GSI·FSI 분포** — 그 범위 안에서 목적을 서로 희생하지 않는 해들이 어떤 밀도에 모이는가.
3. **사람이 고른 대안의 값과 그 이유** — 추적표 행.

**사용자 순서와 다른 점.** 2026-10-24 방향과 이번 요청 ⑤의 순서는 「경주 조직 → 사례 밀도 → 부지 건폐율·용적률 도출 → 그 값을 반영해 최적화」입니다. 이 계획도 같은 순서로 가되 세 곳이 다릅니다. ① 도출 결과는 한 값이 아니라 범위(도출 밴드 표)이고, 그 범위가 등급표를 거쳐 유전자 정의역이 됩니다. ② 방법론의 조직 상단 1.12(띠 (c))는 범위를 자르는 데 쓰지 않습니다. 조직 정합은 규제가 아니므로 자르면 「마스크는 규제 전용」(CLAUDE.md §3.4, D §3.2)과 어긋나고, f₄와 분모도 달라 점검 열로만 보고합니다. ③ 사례 밴드 B는 [가정]이고 사례 실측 근거가 약해(방법론 D-사례-1) 입력이 아니라 사후 점검(「모순 없음 / 있음」)으로 씁니다.

CLAUDE.md §2의 「목적 5개 = 발주 연구 5개 방향 대응」과 다른 목적이 들어가므로 추적표 행을 남깁니다.

### 6.6 대리모델이 필요한가

- **MVP: 필요 없습니다.** 목적·KPI가 ms~1 s 수준이라 정직 평가로 돕니다 [D §6.2].
- **확장판: f₂(조망)에 필요합니다.** 정직 평가 300–1,000개로 LightGBM을 학습하고 홀드아웃 R² ≥ 0.85·MAE를 보고합니다(`config.yaml` `min_r2: 0.85`). 최종 대안의 유전자가 학습 표본 범위 밖이면 R²가 의미가 없으므로 그 안은 정직값으로만 보고합니다(외삽 검사, 실행모델 §3.5-3). f₁을 등시선 방식(K1)으로 루프에 넣을 때도 같은 규칙입니다.
- Ladybug·Radiance·Forma는 어느 판에서도 루프에 넣지 않습니다.

### 6.7 대안 선택 규칙

| 판 | 대안 | 고르는 규칙 |
|---|---|---|
| MVP(3~4목적) | M1 사업성 | 전선은 단가 「중」으로 구하고, 전선 해의 f₃를 단가 밴드 3점(저·중·고)에서 다시 계산해 점마다 f₃ 최선 해를 찾습니다. **세 해가 같을 때만 M1**으로 이름 붙이고, 다르면 「M1 미정(단가 민감)」으로 세 해를 모두 표시합니다 |
| | M2 조직정합 | f₄ 최선 |
| | M3 공공성 | f₅① 최선(기존·계획 성분 병기) |
| | M4 균형 | 전선 안에서 목적마다 순위 백분위로 바꾸고, **가장 나쁜 목적의 백분위가 가장 높은 해**(최악 순위 최대화). 단가 밴드 3점에서 같은 해가 나올 때만 채택하고, 다르면 f₃를 뺀 목적으로 같은 규칙을 적용한 결과를 함께 적습니다 |
| | (보조) 경향 요약 | 정규화한 목적공간에서 K-means 3군집의 대표해(medoid) — 「전선이 어떤 경향으로 갈라지는가」 서술용(KPF 2019의 군집 요약 형식 [T3, 실행모델 §0.3-5]) |
| 확장판(5목적) | A 보존 / B 사업성 / C 접근성 / D 조직정합 / E 균형 | A–D는 f₂·f₃·f₁·f₄ 최선, E는 M4와 같은 규칙(실행모델 §6.1 명칭). B·E에도 단가 3점 규칙 |

- M4·E 규칙은 척도 가중치를 쓰지 않지만, 「목적들을 대칭으로 본다」는 판단은 들어갑니다. 이 판단을 추적표에 남깁니다 [판단].
- 고른 대안은 C-1~C-9를 다시 통과해야 합니다. 두 규칙이 같은 해를 고르면 그 규칙의 차순위 해를 씁니다. 극단해가 다른 목적에서 전선 최하위권이면 그 사실을 대안 설명에 적습니다(고르는 규칙은 바꾸지 않음).
- 「제출 층」(결정도 재현안·대표안·권고안 3안 + 분산 삽입형 1안)은 이 분석 층과 따로 둡니다. 분산 삽입형은 폐선축의 다른 폐역까지 포함하는 S3 문제라 이 엔진이 만들지 못하므로 사람과 규칙으로 별도 작성합니다(CLAUDE.md §5-4, 실행모델 §8.1).

### 6.8 비교안 지배 검사

- V0는 M4′(`inject_lots.py`)로 획지·용도를 그대로 넣고 가구별 d_b를 찾아 근사합니다(§3.7 V0 재현). V0는 축 ① B1 구간 단절로 C-8을 어기므로 **「제약 밖」 비교점**입니다. 목적공간에서는 목적값만으로 V0를 지배하는 전선 해를 찾고, 그 해가 V0보다 나은 목적이 「V0가 희생한 축」이며 회복한 양을 수치로 적습니다(MVP 결과 문장). C-8 위반 자체도 「V0가 희생한 축」(연속성)으로 함께 적습니다.
- V0 재현이 실패하면(연면적 ±5% 밖) V0는 별도 평가 행으로만 두고 지배 검사에 「근사」 표시를 합니다(§8.1).
- 최종 도면(41동)은 고도지구 20 m를 넘는 동이 있어 탐색공간 밖이므로 그림에 점으로만 찍고 「마스크 밖」 표시를 합니다 [산정, D §3.4].
- 18개 비교안은 확장판에서 벡터화(실행모델 §5.4)한 뒤 같은 방식으로 찍습니다.

### 6.9 사람 조정과 추적표

- 절차는 §3.12입니다. 최종안 = 전선 해 하나 + 사람의 조정이며, 모든 조정이 추적표 행으로 남아야 합니다(CLAUDE.md §3.5).

### 8.2 한계

- MVP는 사용자 골격을 고정하므로 「골격까지 포함한 최적」이나 「비교 대상 18개가 희생한 축」을 말할 수 없습니다(§0.4).
- f₂ 조망은 선검사 전 임시 제외라 MVP 대안에는 「f₂ 미평가(선검사 전)」 꼬리표가 붙습니다. f₁은 게이트 카운트 보정 전이라 「미보정」입니다.
- 환경 지표의 루프 안 값은 근사이고, 정밀값은 최종 3~5안에만 있습니다. Forma rapid 값은 Autodesk 스스로 근사로 소개하며 검증 수치를 공개하지 않으므로 상대 비교로만 씁니다 [T4·개발문서, A §3.4].
- V0와 최종 도면은 둘 다 제약 밖 비교점입니다(V0는 C-8, 최종 도면은 고도지구).
- MVP 결과의 꼬리표: 「축 고정(사용자 결정)」, 「f₂ 미평가」, 「f₁ 미보정」, 「허용기준·경관 벡터 없음 — 상수 분기」, 「기준면 확인 전 가정」, 「최저고도 판정 보류」, 「겹 ⑤⑥ 미반영」, 「지하 0 [프로젝트 가정, 시굴 전]」, 「f₅① 인구는 대리값(용도 미구분)」, 「f₃ 방음 항 미반영」, 「EPW 인근 관측소(포항) 대체」 [D §6.4 확장]. 이 꼬리표가 붙은 결과는 학부 과제·내부 검토용이고, 공모·지구단위계획 문서에는 T1–T2 근거와 꼬리표 해소 뒤에만 씁니다(CLAUDE.md §3.1).
- 현재 현황 앵커(사업비 3,822억·면적 79,438㎡·MOU 등)는 대부분 언론 경유 T4이며 원문 치환이 끝나지 않았습니다. 이 계획은 그 값을 계산에 쓰지 않습니다.
