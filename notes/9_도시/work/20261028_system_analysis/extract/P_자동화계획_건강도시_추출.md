## 요약

1. **시스템은 두 층입니다.** 하류는 대지 자동화 엔진([자]: M0~M12, 규칙기반 생성 + pymoo NSGA-III, 가중치 없음, 제약 = 불가능)이고, 상류는 건강 도시 판정·형태 학습([건]: 정주 축 판정 → 판정 고정 → 같은 코드로 형태 측정 → (A) 분포 → 규칙 범위·채점 기준, (B) 형태 템플릿)입니다. **상류 결과를 엔진 어디에 넣는지는 두 문서 모두 정하지 않았습니다** [추출 판단, 표 T6-4].
2. **엔진 고정 입력은 경계 + 사용자 골격**(축 ①~④·화랑로 연결·북측 차도·외곽도로·외곽 보도·진입 7곳)이고, 「고정 입력은 경계선 하나」의 예외라 AU-1이 필요합니다. 유전자는 실행모델 43개에서 가로망 13·단위 축소 6·θ_lot 2를 빼고 보조 골목 2를 더한 R24판입니다 [산정, D §2.5].
3. **데이터 → 알고리즘 반영은 네 겹으로 나뉩니다.** 상한(법정 [T1]) = 마스크, 조직(S2 실측 [산정, 잠정]) = 등급표 산식·f₄, 하한(프로그램 수요 [산정·가정]) = 전역 제약, 사례 밴드 B [가정] = 사후 점검. 「최적 용적률 한 값」은 만들지 않고 도출 밴드 표를 최적화 전에 내며, 결과는 네 분모 × (GSI·물리 FSI·법정 FSI)로 보고합니다 [자 §4].
4. **환경은 세 층입니다.** 루프 안 제약(높이 h_min~h_max·인동 0.5H·축 연속 C-8·매장유산 지하 0) / 루프 안 목적·KPI(f₅①, K3·K5, AU-22면 K9′) / 최종 3–5안 검증(판례 일조·SVF·VSC·바람·소음·UTCI). 층을 합산하지 않습니다 [자 §5.2].
5. **대안은** MVP에서 대안 M1 사업성·M2 조직정합·M3 공공성·M4 균형(3~4목적), 확장판에서 A–E(5목적)입니다. 사업성 이름은 단가 3점에서 같은 해일 때만 붙이고, V0(C-8 위반)·최종 도면(고도 20 m 초과)은 「제약 밖」 비교점입니다 [자 §6.7·§6.8].
6. **건강 도시 판정 결과**는 국내 0곳, 해외 판정 보류 2곳(교토 中京·下京, 's-Hertogenbosch)이고 R3~R7은 어느 도시에서도 산출하지 않아 「건강」 확정은 0곳이며 판별력은 미검증입니다. 경주 원도심은 비건강(예비) — 「학습 대상이 아니라 처방 대상」입니다 [건 요약·§2.4·§2.5].
7. **엔진을 막는 결정**은 AU-1(축 고정)·AU-2(처리본 프레임)·AU-7(용도지역 변경 범위)이고, 건강 도시 쪽은 `judge_rules_v1.yaml` 고정 전에 HU1·HU4·HU12·HU16 등이 닫혀야 합니다.
8. **2026-10-28 파일 확인 결과**, [자]의 첫날(10-27) 산출물(`.venv_gjplan`·`gjplan/__main__.py`·`rhino/site_work_m.3dm`·`requirements_mvp.txt`)은 저장소에서 찾지 못했습니다(아래 「현재 상태」).

#### 최종 역할 [자 §1.3]

- X0 결과와 무관하게 엔진(M2~M8)은 만들고, ⑤ 밀도 도출·⑥ 다목적 최적화·면적표 정본은 AU-0과 상관없이 Python에 남습니다.
- 맡길 일(기본): X0(W1) / 컨텍스트 무대(정점 변환 OBJ 지형, `ctx_fixed` 22,621동 돌출, W5 — AU-0 「주 무대」면 W2 버퍼로) / 최종 3~5안 적재(`floorStack` + `integrateElements`, W6) / 면적지표 교차검증(격자 축척 차 병기 후 ±1% [판단], W6) / 일조·소음·바람 rapid 격자 수치화(SDK 확장 1개, W6) / 일광·미기후·상세 바람 화면 상대 비교(W6) / Site Automation 비교군 1회 S-auto(결과를 대안으로 쓰지 않음, W6) / `buildable`·축 연속성 지면 텍스처(선택).
- 맡기지 않을 일: 루프 안 도로·획지·매스 생성, 규제 4겹 + 2 판정, 밀도 범위 도출, 다목적 최적화, 면적표 정본, 판례 일조 연속성 판정 [A §9.1].
