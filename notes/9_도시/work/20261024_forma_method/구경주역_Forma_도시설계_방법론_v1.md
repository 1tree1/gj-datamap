### 0.1 목적과 「최적」의 정의

사용자가 말한 순서를 뼈대로 합니다.

| 순서 | 질문 | 답하는 절 | 산출 |
|---|---|---|---|
| ① | 경주의 평균 건폐율·용적률, 도로·녹지·하천·주요시설의 경향은 무엇이고, 거리·도시 분위기를 만드는 요인은 무엇인가 | §2 | S2 가구 441개(모델 범위 1,096개) Spacematrix 지표 CSV·요약 JSON(계산 완료), 법정동별 표, 분위기 요인 가설 15개와 판정 |
| ② | 원도심 공동화를 극복한 가까운 사례는 어떤 건폐율·용적률로 개발됐는가 | §3 | 사례 19건 비교표, 밀도 밴드 A~D(밴드 B 수치는 [가정]) |
| ③ | 구경주역 부지의 최적 건폐율·용적률은 얼마인가 | §4 | 상한·조직·하한·사례 네 겹의 교집합 구간(획지 기준, **잠정**), 획지별 표, 추적표 |
| ④ | 그 데이터로 Forma에서 매스·계획을 어떻게 진행하는가(환경 데이터 포함) | §5 | Forma 프로젝트, 단일 격자 시나리오 16개, 환경 지표 6개, 외부 스크립트 비지배 정렬, Rhino 왕복 |

「최적」의 뜻을 먼저 고정합니다. 이 문서에서 최적 건폐율·용적률은 한 값이 아니라 **네 겹(규제 상한·조직 정합·수요 하한·사례 밴드)의 교집합 구간**이며, 그 구간 안에서 환경 성능(일조·일광·바람·소음·미기후·탄소)으로 비지배 해를 골라 사람이 최종 결정하고 추적표에 남기는 것입니다. 가중치를 둔 단일 점수는 만들지 않습니다(CLAUDE.md §4). 교집합의 조직 상단은 기준점 선택에 따라 흔들리므로(§0.7·§4.2) 이번 판의 교집합은 **「잠정」**입니다.

### 0.5 전제 — 매장유산과 지하 [프로젝트 가정, 시굴 전]

- 부지 전역이 매장문화재 유존지역이며 시굴 대상 145,879㎡ [T2, B-002·B-003]. 철도 노반 성토 2 m 미만 [T2, B-002].
- **「지하 연면적 0」은 법정 제약이 아니라 [프로젝트 가정, 시굴 전]입니다.** 고시 제2026-8호 결정조서는 근린공원② 하부 지하주차장 설치를 권장 [T1]하고, CLAUDE.md §5-2는 「지하주차를 1단계에 넣을 수 없다」는 단계 조건입니다. 따라서 기본 시나리오는 지하 0(주차 전량 지상)으로 두되, **시굴 후 2단계 지하 가능 분기 시나리오(V-UG) 1개**를 반드시 함께 돌리고(§4.6·§5.6), 고시의 권장과 가정의 충돌을 추적표 D-지하 행에 기록합니다(§4.7).
- 지하 0은 주차를 지상에 두어 건폐율 하한을 0.08~0.19 밀어 올리는 전제(§4.3)이므로, 이 가정이 바뀌면 밴드 비교 전체가 바뀝니다.
- Forma 내재탄소·면적 지표는 지하를 포함할 수 있으므로 한국 용적률(지상 연면적, 부속 주차 제외; 건축법 시행령 제119조제1항제4호 [T1])과 구분해 기록합니다(§0.6 두 열 규칙).

**두 파레토의 관계 [06 §1-10 반영]**

정본은 CLAUDE.md §2·§4의 `gjplan` 목적함수 5개(f₁ 접근성 … f₄ 조직정합 … f₅)·NSGA-III·**대안 A–E**입니다. Forma의 환경 6지표(일조·일광·바람·소음·미기후·탄소)는 이와 별개의 **2차 검정 축**이며 순서는 「선 gjplan, 후 Forma」입니다. 즉 gjplan 전선 1에서 나온 대안 A–E(또는 gjplan 구현 전에는 §4.6의 밀도 격자 시나리오)를 Forma에 올려 6지표 행렬을 만들고, 그 행렬에 대해 **Forma 밖 Python 스크립트**(자체 비지배 정렬 또는 pymoo `NonDominatedSorting`)로 전선을 뽑습니다. Forma 결과의 전선에는 A–E라는 이름을 다시 쓰지 않고 **「환경 검정 전선 FP-1…FP-n」**으로 부르며, 최종 표는 「대안 X가 환경 축에서 희생한 지표」 형식으로 두 축을 나란히 보입니다. 두 축을 합산하거나 한 축을 다른 축의 가중치로 쓰지 않습니다. Forma 분석 결과를 행렬로 내보내는 경로(CSV·Embedded View SDK)는 **확인 대기**이며, 불가하면 화면값을 수동 전사하고 전사일을 기록합니다.

### 1.3 좌표계·단위·원점

저장소에는 좌표 프레임이 네 가지 섞여 있습니다. 분석·면적은 EPSG:5187에서만 하고, Forma에는 readme가 지정한 CRS(UTM 52N 추정)로 변환해 넣습니다. 모든 식은 평면(x, y) m [산정, 01 §3].

| 프레임 | 쓰인 파일 | EPSG:5179로 되돌리는 식 |
|---|---|---|
| O 콘타 모델(1/2 축척, mm 표기) | `최종콘타모델_v2*.3dm`(숨김 실좌표 레이어 제외) | X = 2·O − C, C = (1,155,149.0, 1,762,445.9). z: 실표고 = (z − 233.85)/0.499 |
| **R 러프 프레임(실축척, mm 표기 = m)** | `구경주역_최종대지_대지경계선.3dm` · `design.json` · `주변건물_정합_v1.3dm` · 채택 매스 v1 3dm | X = R − (11,616.38, −796.58) |
| P 계획 프레임 v3 | `xf_final.json`(P = 2·O + t) | X = P − (12,133.44, −796.58) |
| L 로컬 프레임 | `ctx_fixed.pkl` · `model.pkl` · `key_curves.txt` | X = L + (1,154,983.62, 1,761,896.58) |
| 5179 → 5187 | 처리본 전량 | `pyproj.Transformer.from_crs(5179, 5187, always_xy=True)`(같은 Korea 2000 데이텀, 원점만 다름) |
| 5187 → Forma | 반입 직전 1회 | 5187 → 32652(또는 readme CRS). 원본은 변환하지 않음(CLAUDE.md §1) |
| 5187 → 5174 | 공모 서류 구역계 | 가이드라인 B-004 요구 좌표계 [T1] |

- 검산: 최종대지 3dm 경계 bbox 최소점 R(1,166,702.157, 1,761,153.735) → X(1,155,085.78, 1,761,950.31); 콘타 모델 경계 O(1,155,117.39, 1,762,198.11) → X(1,155,085.78, 1,761,950.32). 두 모델은 **0.01 m** 안에서 같은 땅입니다 [산정, 01 §3].
- 단위: Forma는 m [가정, 지형 readme·OBJ 기준]. 라이노 두 파일은 「mm 표기·1단위 = 1 m」이므로 내보내기 전 단위를 m로 바꾸거나 스케일 1로 내보내는지 확인합니다.
- z 기준이 파일마다 다릅니다(콘타 0.499·표고 + 233.85, 최종대지 3dm 지형 z −63.8~3.5(기준 미확인), 사용자 모델 맥락 건물이 대지판보다 112.4 단위 위 [산정]). **지형 TIN은 수치지도 등고선 F001(175)·표고점 F002(1,351) 절대표고에서 새로 만들고, 건물은 바닥 z를 그 TIN에 앉힙니다.** 기존 3dm의 z는 쓰지 않습니다.
- 높이 산정 기준면과 연결: 고도지구 20 m·15 m가 어느 지표면에서 재는지(건축법 시행령 제119조제1항제5호, 지표면 고저차 시 가중평균 — 조문 원문 확인 대기)는 Forma 지형 z 기준과 같은 문제입니다. 성토 2 m 미만 [T2]·북측 1/3 약 8 m 낮음 [산정]이므로 TIN을 확정하기 전까지 20 m 기반 층수에는 「기준면 확인 전 가정」을 붙입니다(§4.1).
- 사고 사례: 호주 사용자 프로젝트에서 내보내기 CRS가 MGA56(EPSG:7856)에서 WGS84/UTM 56S로 바뀌어 수 km 어긋남 [T4 포럼]. 매 내보내기마다 readme CRS를 확인합니다.

## 3. 공동화 극복 사례의 개발 밀도

### 3.1 비교 규칙

1. 사례 밀도는 분모가 다릅니다(사업구역/획지/가구/순대지). 사례마다 분모를 적고 §0.6 계수로 획지 기준에 맞춘 뒤 비교합니다(환산은 [가정]).
2. 사례의 높이 상한(고도·경관)을 함께 적습니다. 20 m 제약 없는 사례의 FSI는 이 부지 상한을 넘을 수 있어 그대로 옮기지 않습니다.
3. 밴드는 같은 유형(폐역·역세권·공공 주도)의 p25–p75, 단일 사례 값은 점으로만. **설계안 자체(매스 v1)는 사례가 아니므로 밴드 근거에서 제외**합니다(순환 논증 방지, 06 §1-7).
4. 구 안동역·교토 우메코지·부산 혁신도시 분산형은 밀도보다 **순서·분산**의 사례 → 밴드가 아니라 시나리오(분산 삽입형 대안 S-dist)에 반영.
5. 성과지표는 (방문객·체류시간) / (거주인구·생활업종·야간활동) 두 축을 항상 나란히(CLAUDE.md §5-6). 방문객만 늘고 거주가 빠진 것은 회복이 아니라 **치환**입니다.

### 3.6 밴드의 함의와 이식 판단

1. **공동화 극복과 밀도는 상관이 약하고, 거주 축의 유무와 상관이 강합니다.** 저밀 순천은 회복, 저밀 전주는 치환, 고밀 대연은 정주 1위, 저밀(74인/ha) 울산은 섬입니다. → Forma에서 밀도를 움직일 때 **주거 연면적 비중을 고정 입력**으로 두고 상업·문화를 종속 변수로 둡니다.
2. **경주의 상한은 상업 획지에서는 고도지구 20 m, 주거·청사·문화 획지에서는 조례 250%입니다**(06 §2-8 정정). 어느 쪽이든 조례 1,000%·고시 450%·혁신지구 특례의 수치는 실질 상한이 아닙니다. 특례가 고도지구·허용기준까지 미치는지는 확인 대기이며, 경북고시 제2020-479호의 변경 사유가 「현상변경허용기준 수용」 [T1]이므로 고도지구가 풀려도 허용기준이 남아 실질 상한은 유지될 가능성이 높습니다(§4.1).
3. **밴드 C의 유럽 사례는 밀도가 아니라 조문을 빌릴 대상입니다.** 「서측 블록 주거 ≥40%」(Europaallee), 「오픈스페이스 41%·공공공간 선행」(King's Cross), 「보조주택 2,000호↑」(Sonnwendviertel), 「승용차 172대/1,000명·주차 외곽 집약」(Vauban)은 20 m에서도 그대로 쓸 수 있습니다.

## 5. Forma 작업 절차

역할 분담을 먼저 고정합니다. **Forma Site Design = 매스 검토 + 환경 분석 + 발표용 3D 컨텍스트.** 규제 판정·가구·획지 생성·NSGA-III·MILP 단계 계획은 `gjplan`(Python)에서 하고, 결과(3dm)를 Forma로 보냅니다. Site Automation은 비교군으로 1회만 기록합니다. Forma 기능 서술은 02 정본이며 전부 [T4]입니다.

### 5.3 단계 2 — 제약 레이어(buildable envelope)

- §4.1 식으로 획지별 (GSI_max, FSI_max, H_max)를 계산한 3D 볼륨(Rhino)을 OBJ/IFC로 반입해 참조용으로 둡니다(요소 유형·반투명 표시 가능 여부는 02에 근거 없음 → 확인 대기). 매스가 볼륨을 뚫으면 그 안은 생성하지 않습니다(페널티 아님).
- Forma에 없는 제약(사전 절단): **보존지역 조망**(삼층석탑·향일문 조망로 8 m·고분 스카이라인) → Rhino 가시영역 또는 QGIS viewshed로 「조망로에서 석탑·고분이 보이는 각도 비율」 최소값 제약. 이 계산에는 범위 밖 스카이라인(남산·선도산) **광역 DEM이 선행 필요**(미확보, 06 §1-18) / 매장문화재(지하 0 가정·V-UG 분기) / 접근성 f₁(최약점 통과폭)·조직정합 f₄는 `gjplan/evaluate`.

### 5.5 단계 4 — Area metrics 설정

- 지역 기본 규칙에 한국 정의가 있는지 확인(Q3). 없으면 사용자 정의 함수를 **두 개** 추가(함수별 연면적 차감식을 지표로 정의할 수 있는지는 F5 확인 대기): **물리 FAR = 지상 GFA 전체 / 획지**, **법정 용적률 = 지상 GFA − Parking 함수 연면적(부속 주차) / 획지**; **건폐율 = 최대 층 투영면적 / 획지**. 지하층 제외가 불가하면 Forma 수치는 참고치, `gjplan` 면적표가 정본.
- Function: Residential / Commercial / Public(청사·문화) / **Parking** / Unspecified. RA 승수(예: Commercial 0.8)는 쓰지 않음(한국 산정에 없음). GFA는 외곽 면적만 세고 내부 코어·복도를 반영하지 않음 [T4] → 법정 연면적과 차이 가능.

3. **Forma 밖 Python 스크립트**로 비지배 정렬(자체 구현 또는 pymoo `NonDominatedSorting`)을 수행해 전선 1을 뽑습니다. Forma Site Automation은 파레토 최적화기가 아닙니다 [T4 기능 서술에서 추론, F15 확인 대기]. **가중치·점수 합산 금지.**
4. 전선 1을 **환경 검정 전선 FP-1…FP-n**으로 이름 붙입니다(대안 A–E는 gjplan f₁–f₅ 전선의 명칭으로 유보, §0.9). 각 전선 해가 희생한 지표를 표로 보이고, 선택은 사람이, 이유는 추적표 D-Forma-1 행에.
5. rapid로 격자를 거르고 detailed(바람 CFD·소음)는 전선 1에만 씁니다.
6. 결과를 §2.7 절차로 5187에 되돌려 S2 island 산점도 위에 찍고 「밴드 안/밖」(물리 FSI)을 함께 보고합니다.
7. gjplan이 구현되면 순서를 「gjplan 전선(대안 A–E) → Forma 6지표 검정」으로 바꾸고, 격자 시나리오는 gjplan 전선 해로 교체합니다.
